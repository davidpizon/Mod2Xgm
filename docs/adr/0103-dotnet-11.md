# ADR 0103: .NET 11 and System.CommandLine 3

- **Status:** Accepted (David, 2026-11-11)
- **Date:** 2026-11-11

## Context

David moved his machine to the .NET 11 SDK (11.0.100, the only SDK installed) and updated System.CommandLine from 2.0.14
to 3.0.0, a major version ([ADR 0017](0017-cli-parsing.md) chose the library). The repository, CI, the release build and
the nightly audit were still on .NET 10. On .NET 11 with System.CommandLine 3, three converter tests failed:

- Two usage-error tests. System.CommandLine 3 rewords the missing-argument error to `Required argument 'input.mod'
  missing for command: 'Mod2Xgm'.`, and `CommandLineDefinition` found a missing input by the old wording's start,
  `Required argument missing`.
- The perceptual features' speed test (plan T9.4k1, [ADR 0100](0100-perceptual-features.md)). In a Debug build, one pitch
  region's fastest run took 20.7–21.9 ms against the 20 ms budget. A Release build still passes it.

## Decision

David chose (2026-11-11):

- **The whole repository targets .NET 11**: one `net11.0` in `Directory.Build.props`. CI, the release build and the
  nightly audit install .NET 11 (`11.0.x`). AGENTS.md, the README and the notices say .NET 11.
- **System.CommandLine 3.0.0 stays.** `CommandLineDefinition` now tells a missing input from the parse result: an error
  on the input argument with no tokens. It no longer reads the message, so a later rewording can't break it. The
  converter's own message, `Required argument missing: <input.mod>.`, is unchanged (docs/cli.md).
- **The speed budget is 25 ms** per pitch region, up from 20 ms. It is still checked on the fastest of 9 runs.

The test packages move with it: Microsoft.NET.Test.Sdk 18.12.0 and Microsoft.Testing.Extensions.HangDump 2.5.3.

## Options considered

- **Move everything to .NET 11 (chosen).** One target, the one David builds on, and CI checks what he runs.
- **Keep the repository on .NET 10 and only make the code work on both.** CI would then check a framework David no longer
  has installed.
- **Go back to System.CommandLine 2.0.14.** A smaller change, but it stays behind the major version, and the
  missing-input check would still rely on the message text.
- **Make the features faster to keep 20 ms.** Possible later. Release builds, which the harness runs, already meet it.

## Consequences

- Native AOT publishing on win-x64, linux-x64 and osx-arm64 now uses the .NET 11 toolchain; CI's AOT jobs check it.
- `PerceptualMetricsTimingTests` uses a named budget of 25 ms. ADR 0100's 20 ms is amended by this ADR.
- Qodana (`jetbrains/qodana-cdnet:2026.2`) has to read .NET 11 projects. If it can't, its image is updated in a later PR.
